# Implementation: how the work is split

The specification is in this folder (SPEC.md and the documents it
indexes); this page is how four parallel workstreams build it without
stepping on each other: who owns which files, the contracts between them,
how to build and check, and the conventions every script follows.

## 1. The skeleton (already working)

```
rive.yaml               the Rive project (name avalanche, main Main); excludes build, world/psx, tools, assets
make_rml.py             writes avalanche.rml (the Rive side)                          [UI]
avalanche.rml           generated
hedra_engine/ hedra_shaders/   vendored and generated by `hedra build` (commit them, never edit)
tools/pins.py           the pins table: the world <-> Rive contract                    [shared, append-only]
tools/make_run.py       writes world/run.rscn and world/scripts/pins_data.as          [COURSE]
world/hedra.yaml        main scene run.rscn, MSAA off, sources not embedded
world/run.rscn          generated: the PSX frame rig, Course + Rider instanced, Lens, Sound, Pins
world/psx/*.wgsl        the psx-style shaders (copied from .claude/skills/psx-style)
world/course/course.rscn       PLACEHOLDER slope                                     [COURSE]
world/rider/rider.rscn         PLACEHOLDER box                                       [GAMEPLAY]
world/scripts/game_state.as    the shared state module `game`                        [shared, append-only]
world/scripts/course_api.as    the course API, PLACEHOLDER bodies                    [COURSE: bodies; signatures fixed]
world/scripts/pins_data.as     generated from tools/pins.py
world/scripts/run.as           PLACEHOLDER driver                                    [GAMEPLAY]
world/scripts/camera.as        PLACEHOLDER chase camera (on LowRes/Lens)             [GAMEPLAY]
world/scripts/sound.as         PLACEHOLDER (on the Sound node)                       [AUDIO]
```

Verified end to end (hedra 0.1.0, rive dev-8d3a7cc3): the bake succeeds,
the frame passes `psx_audit.py frame`, the world writes a pin that
`--data-dump` reads (`data/speedKmh`), and a world script can start a
Rive `AudioProcessor` (`Audio.start` from a NodeScript; `--render-audio`
captured it).

## 2. The four workstreams and what each owns

A workstream edits only its own files. A change another owner's file
needs is written in the final report under "Requests", not made.

| Workstream | Owns | Builds |
|---|---|---|
| **COURSE** (the mountain and the look) | `tools/course/**`, `tools/make_textures.py`, `tools/make_props.py`, `tools/make_run.py` (but not its pins loop), `world/course/**`, `world/props/**`, `world/textures/**`, `world/scripts/course_api.as` (bodies), `world/scripts/course_data*.as`, `world/scripts/daylight.as`, `world/scripts/fx_*.as` | COURSE.md: the generated course (terrain, every feature, rails, the split, the mega-jump, fall zones, respawn data, obstacles), the dressing (trees, chalets, lifts, banners, arches), procedural PSX textures, the sky and fog, the sunset (LOOK.md, section 3), the course-side effects (lens flare, confetti, falling snow) |
| **GAMEPLAY** (the rider and the rules) | `world/scripts/run.as`, `rider.as`, `grind.as`, `tumble.as`, `tricks.as`, `camera.as`, `input.as`, `autopilot.as`, `reference_run.as`, `world/scripts/lib/**`, `world/scripts/*_test.as` of these, `world/rider/**`, `world/lab.rscn`, `tools/make_rider.py`, `tools/make_poses.py` | RIDER.md and TRICKS.md: the physics, tricks, scoring, combos, landing, grinds, crash and respawn, the phases (title, countdown, run, finish, results, initials), restart, the table, the cameras, the input (keys; the pad through the `pad*` pins), the autopilot, the segmented rider and its poses, the rider's effects (spray, blob shadow, trail, sparkle), every pin written |
| **UI** (the Rive side) | `make_rml.py`, `avalanche.rml`, `ui/**` (2D scripts), `fonts/**`, `tools/make_ui*.py` | RIVE.md: GameData and Game, `Main` and its overlays (title, HUD, results, initials, pause, wipe, captions), the state machines, the trick text composed from the pins, the pad script (`ui/pad.as` writes `padX`, `padY`, `padButtons`), the 320 x 240 grid, fonts |
| **AUDIO** (all sound) | `world/scripts/sound.as`, `world/scripts/audio/**`, `audio/**`, `tools/make_music.py`, `tools/make_voice.py` | AUDIO.md: the `Spu` processor, voices, the board, the music and its states, the announcer, UI sounds, the captions' line ids |

Shared, append-only: `tools/pins.py` (add rows at the end of their group;
never rename or remove) and `world/scripts/game_state.as` (add fields and
constants; never rename or change a meaning). The lead merges.

## 3. Contracts

### The state module (`world/scripts/game_state.as`)

One module global, `game`. GAMEPLAY writes `game.phase`, `time`, `score`,
the combo, `countdown`, `game.rider` (every field, every tick),
`game.trick`, `game.results`, `game.table`, `game.settings` (from the
pins) and pushes `game.events` (the `EV_*` codes). AUDIO reads all of it
and writes `game.audio`. COURSE's daylight and effects read `game.rider`.
The event ring is never cleared: each reader keeps its own cursor and
reads from it to `game.events.written` (at most `EVENT_RING` behind).

### The course API (`world/scripts/course_api.as`)

Every function, class and constant there keeps its signature and meaning;
COURSE replaces the bodies (they are a placeholder slope today). The
frame: metres, Y up, the course down -Z from the origin, +X right going
down. `ground()` is the rideable surface (terrain, kickers, tables, roofs),
`lineSample`/`nearestSample` the line, `railPoint` the grindable curves,
`obstacle` the cylinders to crash into, `feature` the jumps for the
autopilot and the music, `inFallZone`, `respawnAt`, `sunAt`. GAMEPLAY
uses nothing else of the course. Its cost: `ground()` under 2 µs.

### The pins (`tools/pins.py`)

The GameData view model, one property per row. GAMEPLAY writes the `out`
rows (through `pins_data.as`'s `PIN_PATHS`; a number in the node's
`position.x`, a boolean in its `visible`, written only when it changes)
and reads the `in` rows every frame. UI declares GameData from the table
and binds the HUD to it, and writes the `in` rows from its menus and the
pad script. AUDIO reaches the view model through GAMEPLAY's pins only
(`captionLine`, `captionSeq`, `beat` are written by GAMEPLAY from
`game.audio`).

### Scenes

`world/run.rscn` is generated by `tools/make_run.py` and instances
`course/course.rscn` (as `LowRes/Course`) and `rider/rider.rscn` (as
`LowRes/Rider`): their roots are their owners'. The Lens
(`LowRes/Lens`, `camera.as`), the Sound node (`Sound`, `sound.as`) and
the root (`Run`, `run.as`) carry the scripts. Things GAMEPLAY needs in
the scene go under the rider's scene; things COURSE needs go in the
course's scene or in `make_run.py`.

## 4. Building and checking

```sh
export RIVE_VERSION=dev-8d3a7cc3      # the pinned rive (tools/pins.env of the Hedra repo)
python3 tools/make_run.py && python3 make_rml.py
hedra build world                     # builds the scenes, vendors hedra_engine
rive . --unsigned-riv                 # bakes build/avalanche.riv (about 40 s); errors in build/problems.log
rive . --screenshot=build/shot.png --viewport=960x720 --advance=180
rive . --screenshot=build/shot.png --viewport=960x720 --advance=180 --data-dump=build/dump.txt --data-dump-every=60 --data-dump-filter='data/*'
rive . --key=space:down ...           # scripted input: `rive docs workflow`
rive . --render-audio=build/a.wav --advance=5s
rive . --test                         # the Tests scripts (*_test.as)
hedra check world/run.rscn            # a scene's problems
hedra render world/course/course.rscn -o build/c.png --size 960 720 --msaa off   # a sub-scene alone, no scripts
python3 .claude/skills/psx-style/scripts/psx_audit.py frame build/shot.png
```

## 5. Conventions learned building the skeleton

- AnimaScript: no union types (`T?` for nullable); `_process(delta: f32)`;
  `_ready()`, `_input(event: InputEvent)`; imports from
  `"hedra_engine/script"`; `Mathf` for f32 maths; StaticArray literals for
  tables; allocate nothing per frame.
- `.rscn`: XML; a comment may not contain `--`; `format="2"` for
  `mode="to_source"` bindings; scripts as `ext_resource type="Script"`;
  instances as `instance="ExtResource(&quot;id&quot;)"`.
- The shader world frame is Z up (psx-style SKILL.md, "Engine gaps").
- `hedra build world` after any scene or asset change, then bake.
- Commit the generated files (`avalanche.rml`, `run.rscn`, `pins_data.as`,
  `course_data.as`, `hedra_shaders/`, `hedra_engine/`); never `build/`.
- No image generator and no person's approval in these workstreams: art
  is procedural (scripts in `tools/` drawing PSX-style textures and
  low-poly models), marked as placeholders for the asset pipeline
  (ASSETS.md), and must still pass `psx_audit.py`.
